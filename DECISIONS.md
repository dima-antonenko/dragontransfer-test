# Решения

Короткие записи о том, почему код устроен так. Новое решение добавляется следующим номером,
старое не переписывается молча: если поведение изменилось, в старой записи появляется ссылка на новую.

## 1. Сервисные объекты, как в rate_me_telegram

Контроллеры только принимают параметры и рендерят результат. Сценарий — класс
`Namespace::Action < BaseService` с `#call`.

Так HTML-экран заявки и `GET /api/orders/:id` вызывают один `Orders::Show`.
Спека сценария не поднимает HTTP.

## 2. Partner API изолирован в клиенте

Все HTTP-вызовы партнёра идут через `DragonTransfer::Client`. Сервисы сценариев
получают клиент аргументом `client:`. В проде `BaseService#client` создаёт настоящий клиент,
в спеках передаётся `instance_double`.

Парсинг конверта `{ success, payload, id }` и перевод ответа в `DragonTransfer::Error`
живут в клиенте, а не копируются по сервисам.

## 3. Ключ партнёра только на сервере

`DRAGONTRANSFER_API_KEY` читается из ENV и уходит в заголовок `X-Api-Key` исходящих запросов.
Во фронтенд, в JSON заявки и в репозиторий он не попадает.

Входящий webhook проверяется тем же секретом: `DragonTransfer.valid_api_key?`
(`secure_compare`, отказ при пустом ключе или разной длине).

## 4. Сначала локальная заявка, потом партнёр

`orders/create` требует `verification_return_url` и `invoice_return_url` с id заявки,
по которому пользователь вернётся в Mini App. Этот id — локальный integer, его нет,
пока строка не сохранена. Поэтому `Orders::Create` делает `save!`, затем вызывает партнёра.

Если партнёр ответил ошибкой, локальная строка удаляется. Иначе в базе остаются
черновики без `external_id`, а пользователь видит отказ. Валидация модели происходит
до HTTP: при невалидных полях партнёр не вызывается.

## 5. Два идентификатора

`orders.id` — ключ UI и return URL. `orders.external_id` — UUID партнёра для webhook
и `orders/find`. Смешивать их нельзя: партнёр не знает локальный id, браузер не должен
опрашивать партнёра напрямую.

## 6. Статус монотонный

Webhook и опрос могут прийти не по порядку. `Order::STATUS_RANK` отбрасывает статус
с меньшим рангом. `SUCCESS` и `ERROR` оба финальные и равны по рангу: из одного финала
в другой через payload не перейти.

`Orders::SyncStatus` не ходит в `orders/find` для финальной заявки и для заявки без `external_id`.

## 7. Webhook неизвестной заявки — 200

`Webhooks::DragonTransfer::Process` не создаёт заказ по входящему payload.
Если `external_id` не найден, метод возвращает `nil`, контроллер отвечает `200`.
Партнёр не получает 404 и не ретраит чужой или уже удалённый id.
Неверный ключ по-прежнему `401`.

## 8. Суммы — строки

Колонки сумм и курса — `string`. Клиент приводит amount к `BigDecimal` и в JSON
кладёт integer, если дробная часть нулевая, иначе float только на границе JSON партнёра.
Внутри приложения деньги не считаются через `Float` и не хранятся в `decimal` без отдельного решения:
формат партнёра сохраняется как есть.

## 9. Пара RUB → USDT TRC20 зафиксирована

Продукт первого этапа — покупка USDT в сети TRC20. `payin_currency` при создании всегда `RUB`.
Адрес проверяется регекспом `Order::TRC20_ADDRESS` (начинается с `T`, base58, 34 символа).
Выбор сети, другой валюты или `fee_value` в UI нет. Метод клиента `precalc` умеет `fee_value`,
сценарий его не передаёт.

## 10. Публичный JSON API без учёток

Нет Devise и своих пользователей. Mini App и браузер ходят в `/api/*` без токена.
CSRF для API снят (`null_session`), для webhook — `skip_forgery_protection`.
HTML-`fetch` всё равно шлёт `X-CSRF-Token`.

Осознанное ограничение: любой, кто знает локальный `id`, может прочитать заявку.
Секрет партнёра при этом не раскрывается.

## 11. telegram_user_id не является входом

Mini App читает `Telegram.WebApp.initDataUnsafe.user.id` и кладёт его в тело `POST /api/orders`.
Сервер сохраняет число как есть и **не** проверяет подпись `initData`.
Поле нужно, чтобы позже связать заявку с пользователем Telegram. Сейчас по нему нельзя
ни авторизовать, ни фильтровать чужие заявки.

## 12. Бот отложен

Репозиторий не поднимает Bot API. Точка входа в Telegram — URL Mini App, который
указывается в BotFather отдельно. Пока этого нет, тот же интерфейс открывается по `APP_HOST`.

## 13. Статус тянется и webhook'ом, и опросом

Партнёр шлёт webhook на `POST /webhooks/dragon_transfer`. Пока заявка не финальная,
`miniapp.js` дополнительно опрашивает `GET /api/orders/:id` каждые 20 секунд.
Опрос страхует случай, когда webhook не дошёл (локальный туннель, пропущенное событие).
Оба пути пишут одни и те же поля через `apply_remote_payload!`.

## 14. Тесты мокают клиента, сеть выключена

Сервисные спеки внедряют `instance_double(DragonTransfer::Client)`.
Request-спеки подменяют сервис. `WebMock.disable_net_connect!` не даёт спеке уйти
на `test.dragontransfer.online`. Общий payload партнёра — `partner_payload` в
`spec/support/partner_api_helpers.rb`.

## 15. Часовой пояс Москвы

`config.time_zone = "Europe/Moscow"`. Сроки `invoice_expires_at` и
`verification_expires_at` парсятся через `Time.zone.parse`.
